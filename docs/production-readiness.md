版本：v0.1（评估草案）

适用快照：当前工作区，包含已有未提交修改

## 1. 结论

项目已具备较完整的个人 Agent 工作流：浏览器交互、模型流式输出、工具执行、子 Agent、SQLite 会话存储、记忆、技能和用量记录。

下一阶段应优先建设“可取消、有限额、可恢复”的任务执行层。长期本机使用需要先补齐执行可靠性；多人使用还需要身份认证、数据归属与执行隔离；对外部署则需要服务治理、监控、备份和发布流程。

Checkpoint 的具体实施任务、恢复边界与验收要求见 [Checkpoint v1：交给 AI 的实施说明](checkpoint-implementation.md)。

现有主循环、工具注册方式和 SQLite 可以作为下一阶段的基础。数据库和服务拆分应根据并发、部署方式与恢复目标决定。

本文按三个使用范围设定验收门槛：

| 使用范围 | 使用假设 | 必须优先解决 |
| --- | --- | --- |
| 本机可靠版 | 单一使用者、本机运行、受控任务 | 取消、预算、上下文兜底、恢复、写入保护、备份 |
| 小团队试用版 | 多个身份、多个任务、可能操作不同项目 | 本机可靠版能力，以及认证、数据归属、执行隔离、并发限制 |
| 对外生产版 | 远程访问、持续运行、明确服务目标 | 前两阶段能力，以及生产服务层、监控告警、容量与故障验证、发布回滚 |

使用范围仍待产品决策确认。认证和隔离是多人使用前的门槛，不能等到公开上线才补。

本版依据本次对话中对 README、主要 Python 模块、前端相关代码、现有设计文档和测试结果的检查。结论采用以下证据等级：

| 等级 | 含义 |
| --- | --- |

| 后果待复现 | 可从实现推出风险，但尚未通过相应故障或并发实验验证 |

## 3. 当前架构与已有基础

```text
浏览器界面
  → server.py：接收请求、取得会话锁、建立轮次
  → app.py：组装提示词、记忆快照、技能与工具
  → agent.py：模型请求 → 工具执行 → 结果回填 → 下一回合
  → sessions.py：原始消息、展示事件、工作上下文和轮次状态
  → 浏览器：展示进度与最终结果
```

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 会话互斥 | 同一会话执行与删除使用同一把锁 | 不同会话仍共享工作目录和宿主机资源 |
| 数据库启动独占 | 先取得数据库文件锁，再打开库和处理遗留任务 | 当前以单服务进程持有数据库为前提 |
| 最终保存一致性 | 最终工作上下文与轮次终态在同一事务保存 | 普通工具回合尚未持续保存工作上下文 |
| 保存失败提示 | 页面区分执行结果与保存状态；可在进程内保留待补写结果 | 待补写的内存数据不能跨进程崩溃恢复 |
| Shell 结果表达 | 区分退出码、超时、启动失败、标准输出和错误输出 | 输出捕获和子进程树清理仍需完善 |
| 共享写入保护 | 编辑、记忆、技能管理已使用部分路径锁；技能文件使用原子替换 | `write_file` 仍直接覆盖；保护未覆盖所有写入途径 |
| 用量记录 | 按会话、轮次和主／子 Agent 记录模型用量 | 记录尚未形成统一的预算执行机制 |

主要依据：[server.py](../server.py)、[sessions.py](../sessions.py)、[dblock.py](../dblock.py)、[tools/bash.py](../tools/bash.py)、[tools/filelock.py](../tools/filelock.py)、[usage.py](../usage.py)。

## 4. 主要差距

这里的 `error` 表示多人或对外服务的上线阻塞项，`warning` 表示执行可靠性缺口，`info` 表示运维与交付能力待完善。级别不代表已复现了对应事故。

| 编号 | 级别 | 差距与影响 | 证据与位置 |
| --- | --- | --- | --- |
| P01 | error | 缺少用户认证和资源归属校验。多人共享服务时，会话、文件、记忆与凭据需要按身份隔离 | 代码已确认：[server.py](../server.py) 的请求入口、[sessions.py](../sessions.py) 的数据模型 |
| P02 | error | 工具在宿主机权限下执行。Shell 黑名单及部分文件工具的越界确认，不能建立操作系统级隔离 | 代码已确认：[hooks/permission.py](../hooks/permission.py)、[tools/bash.py](../tools/bash.py) |
| P03 | warning | 缺少贯穿执行链的取消、总时长和统一用量预算；最大 1000 回合不能代替任务预算。Shell 超时只处理直接子进程，输出先全量捕获再截断 | 代码已确认／功能缺口：[config.py](../config.py)、[agent.py](../agent.py)、[tools/bash.py](../tools/bash.py)、[tools/subagent.py](../tools/subagent.py) |
| P04 | warning | 普通工具回合缺少持久化工作上下文；重启主要将遗留轮次标为失败。请求缺少幂等标识，重复提交可能再次执行已有副作用 | 代码已确认，重复执行及崩溃后果待复现：[server.py](../server.py) 的 `_run_turn`、`_checkpoint`，[sessions.py](../sessions.py) 的 `begin_turn`、`reap_running` |
| P05 | warning | 自动压缩仅运行第 1 档。其余三档关闭后，累计对话没有完整自动兜底，主要依赖模型主动调用 `compress` | 代码已确认：[context.py](../context.py) 的 `ContextCompactor.prepare` |
| P06 | warning | 文件保护不一致。直接覆盖写入、编辑器、Shell 与多个会话之间仍可能互相覆盖；进程内锁不能覆盖外部写入 | 代码已确认，部分并发后果待复现：[tools/write.py](../tools/write.py)、[tools/edit.py](../tools/edit.py)、[tools/memory.py](../tools/memory.py) |
| P07 | warning | 请求体缺少大小上限，任务直接运行在 HTTP 请求线程中，缺少有界任务队列和全局并发控制；历史与用量读取会随数据量增长 | 代码已确认：[server.py](../server.py) 的 `_json_body`、`_run_turn`、`_get_turns`，[usage.py](../usage.py) 的读取逻辑 |
| P08 | info | 尚未形成完整的健康检查、告警、备份恢复、数据保留、自动化发布和效果评估流程 | 已检查仓库范围内的功能缺口，部署侧设施尚未核实 |

### P01／P02：访问与执行权限

多人使用时，登录身份必须参与每一次会话、文件、任务和产物访问的授权。项目记忆、用户记忆和模型凭据需要明确归属。

执行侧应使用受限账户或隔离环境，限制文件系统、网络、进程、内存和磁盘访问。权限控制需要覆盖 Shell、文件工具、子 Agent 和未来外部执行器。提示词中的约定不能单独承担这些限制。

### P03：任务控制与预算

增加任务级取消信号和截止时间，贯穿模型请求、等待重试、用户确认、工具执行和子 Agent。取消后应停止派发新操作，并在约定时限内清理受控进程树。已经完成的文件修改仍需如实记录。

预算应覆盖主 Agent、子 Agent 和生图等外部调用，在派发前检查剩余预算并限制单次输出；完成后结算实际用量。并发调用需要预留预算，结果未知的调用应保留不确定状态，避免只依赖事后账本控制成本。

### P04：恢复和重复提交

原始消息、展示事件与工作上下文是三份不同用途的数据。历史页面能看到某条工具结果，并不表示恢复后的模型上下文已包含它。

建议在完整工具回合边界保存检查点，并持久化工具执行前后的状态。请求加入幂等键，重复提交时返回已有任务。对“外部操作已经发生，但执行结果尚未落库”的情况，记录为结果未知，优先查询或核对实际状态；不可安全重试的操作需人工处理。不能仅依靠重放日志承诺任意 Shell 操作恰好执行一次。

### P05／P06：上下文与文件完整性

恢复压缩前，应处理消息编号保留、工具调用与结果配对、当前任务保留、原文取回和压缩失败退路。验收应经过实际 `prepare()` 调用链。

文件写入应统一使用原子替换和版本冲突检测，明确哪些写入共用锁。原子替换解决半写文件问题，冲突检测解决旧内容覆盖新内容问题。并行修改同一项目时，可按任务分配独立工作目录，再显式合并结果。

### P07／P08：服务、数据和运维

增加请求体限制、读取超时、历史分页、全局并发限制和有界队列；让任务执行与浏览器进度连接拥有独立生命周期，并定义断开连接后的继续或取消行为。

对外部署需要采用适合生产运行的 HTTP 服务层。Python 官方明确说明 `http.server` 只提供基础安全检查，不建议用于生产环境，见[官方文档](https://docs.python.org/3/library/http.server.html)。

建立结构化日志、任务状态与错误指标、失败告警、健康检查、优雅退出、自动化构建测试和发布回滚流程。会话库、记忆、技能、归档和图片等产物应有一致的备份、保留与清理策略；备份需要通过恢复演练验证。升级涉及数据库迁移时，应同时验证代码与数据的回退方案。

## 5. 分阶段实施路线

阶段是建议工作顺序，不是当前进度或工期承诺。

| 阶段 | 交付重点 | 完成门槛 |
| --- | --- | --- |
| M1：本机可靠版 | P03～P06 为主；补充基本日志、备份与统一测试环境 | 任务可取消、预算可执行、长对话有兜底、崩溃后可解释并恢复、共享写入不静默覆盖 |
| M2：小团队试用版 | P01、P02；P07 的队列、任务执行与连接分离、并发限制 | 不同身份的数据和执行环境隔离；重复请求不重复派发；达到选定并发目标；远程访问时同时具备可靠服务层与传输保护 |
| M3：对外生产版 | 完成 P07、P08，建立发布与效果评估门槛 | 容量、故障、备份恢复、升级回滚、权限与效果回归均有可复查结果，并达到约定服务指标 |

M1 建议拆成可独立验收的改动：任务控制对象与取消机制 → 总预算与资源限制 → 压缩链路恢复 → 回合检查点和请求去重 → 文件写入完整性。实施时继续保留现有会话互斥与最终事务保存约束。

## 6. 验收场景

数值门槛需在实施前确定，例如取消响应时限、最大并发、单任务预算、允许的数据损失窗口和恢复时长。

| 场景 | 验收要求 |
| --- | --- |
| 模型请求、Shell、子 Agent 或等待确认时取消 | 在约定时限内响应取消；不再派发新操作；受控进程树被清理；已发生的副作用有记录 |
| 工具完成后、结果保存前强制终止服务 | 重启后能区分已完成、未执行和结果未知的操作；提供恢复依据；不盲目重复执行 |
| 同一请求重复提交 | 返回同一任务或明确冲突，不创建重复执行；覆盖执行中和执行完成后的重复提交 |
| 累计用量达到预算、子 Agent 消耗预算 | 预算统一结算；后续调用被阻止或进入明确终态；不会因嵌套调用绕过限制 |
| 长对话与超大工具输出 | 自动压缩链路实际触发；编号仍可使用，调用与结果保持配对；当前任务和关键状态可保留 |
| 两个会话写同一文件 | 合并成功或明确报告冲突；不静默丢失修改；覆盖直接写入与编辑交叉执行 |
| 数据库写入失败、磁盘满、模型超时或限流 | 页面与持久化状态一致地说明失败和不确定性；重试次数有界，副作用不会被无条件重放 |
| 断开浏览器并重新连接 | 按定义继续或取消任务；重连后进度可恢复，事件不会错误重复，待确认问题可正确处理 |
| 非所属用户访问会话、文件或图片 | 授权被拒绝；资源标识不可代替权限校验；工具不能访问其他身份的执行环境 |
| 升级、回滚与备份恢复 | 使用独立测试数据完成演练；会话、上下文与产物引用保持一致；迁移兼容性可验证 |
| 固定真实任务集回归 | 按可验证结果统计完成率、错误执行、耗时与成本；不以模型自述完成作为唯一成功依据 |

## 7. Codex 生图的接入位置

生图属于后续工具扩展，可复用任务执行层。建议流程：

```text
DeepSeek 主 Agent → image_generate 工具 → 受控的 Codex 执行任务
  → 保存图片和产物元数据 → 关联当前会话 → 浏览器展示
```

目前确认本机 Codex CLI 存在并启用了 `image_generation` 功能；尚未实测“Python → Codex 非交互生图 → 返回图片路径”的完整流程，因此该接入仍属于待验证方案。

首个原型只验证一张图的生成、文件落盘和结果返回。通过后再接入任务状态、取消、超时、产物访问控制、配额耗尽处理和错误记录。图片落盘，Agent 上下文保留说明与产物标识，避免把大段图片编码写入会话文本。

内置生图与独立 Image API 的额度和计费口径应分别处理，不能直接套用现有 DeepSeek 价目表。官方提供[内置生图说明](https://learn.chatgpt.com/docs/image-generation)和[Image API 文档](https://developers.openai.com/api/docs/guides/image-generation)。服务化时应另行确定执行方式与凭据归属。

## 8. 当前验证基线

2026-09-23，本次对话中的两次现有测试全量执行结果均为：**281 passed、2 failed、1 skipped**。

失败项：

- `tests/test_bash.py::test_超时是独立状态不是退出码`：预期超时，实际返回退出码 127，输出显示 `sleep: command not found`。
- `tests/test_bash.py::test_超长时状态仍可见_截断标在尾部`：预期成功，实际返回退出码 127，涉及 `head`／`tr` 命令的执行。

临时补充测试进程的 Git Bash 工具路径后仍然复现，根因尚未完全定位。第一次执行另有 pytest 缓存写入警告；第二次禁用缓存插件后，两项失败仍存在。跳过项的原因本轮未进一步核实。

本机首页探测返回 HTTP 200，页面标题为“小鲸的工作台”。这只验证页面可访问，不代表模型调用、工具执行、浏览器完整交互或生产故障场景已经验收。
